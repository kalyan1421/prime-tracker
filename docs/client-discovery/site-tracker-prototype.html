What this prototype is showing

The grid ports the monday board's columns, minus the ones that were not worth porting. Three panels below have shipped; two are next; two are deliberately not being built.

Delivered

Blocker, priority, work type, owners

None of these existed on Unit. Blocker carries a reason and an age, so the grid can say “blocked for 11 days” — the board's is a bare yes/no. Its stray “DONE” priority value is deliberately not ported: completion is the checklist percentage, not a priority.

Delivered

Versioned checklist templates

Expand any row: the checklist names its template and version, stamped at creation. Five step lists had already drifted apart on the board because nothing recorded which one a unit came from — and measuring this database first found the same fault here, five lists across fourteen units.

Delivered

This grid

Grouped property → building, with a status battery and average completion per group. The percentage ring is a number the source board shows nowhere. Tenant identity is hidden from roles that cannot read leases, which includes the Construction team most likely to be using this screen.

Next

One canonical update feed

Per-unit updates now exist and post from this panel. Still to come: threaded replies, a source chip on every post, and one shared feed component used on the unit page, the building page and here — folding three overlapping comment surfaces down to one.

Next

Email and WhatsApp ingestion

A per-unit inbound address so the field crew can post by replying to an email or sending a message, photos included. The audit's own pick for the highest-value integration: everything else on the board is manual data entry.

Cut from scope

AI summary columns

The board generates a “Latest update” and a “Next action” per unit from the feed. Built, then removed at the client's direction — the operational tracker is the product; the summarisation layer on top is not wanted for now.

Skipped

Vibe views, agents, workflows

All empty scaffolds on the real board. Also skipped: the parent Timeline column (0 of 25 rows used) and the two duplicate untitled text columns (4 values across 540 rows).
